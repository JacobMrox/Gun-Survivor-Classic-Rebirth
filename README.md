# Why

## English
Biohazard: Gun Survivor (known in China as 惡靈古堡：生存遊戲 and internationally Resident Evil: Survivor) was released on PC exclusively in China and Taiwan, and that version has long been infamous for its instability, bugs, and poor technical implementation. On modern systems, the game is extremely difficult—if not impossible—to run properly due to outdated APIs, broken dependencies, and compatibility issues.

Inspired by [Classic Rebirth](https://classicrebirth.com/) by Gemini-Loboto3. This project exists to modernize and preserve the PC version of Gun Survivor by replacing legacy systems with modern, stable alternatives. The goal is not only to make the game playable on current hardware and operating systems, but also to improve its overall usability, performance, and configurability—without altering the original experience.

Another reason being is that this is the first RE/BIO game i actually owned, and I have fond memories of it. 

In short, this project aims to:

* Restore playability on modern Windows systems
* Replace obsolete or broken APIs
* Fix long-standing bugs and technical issues
* Add quality-of-life improvements and configuration options
* Lay the groundwork for further enhancements and modding

- Debug menu utilities (F2/F10 → UTILITY MENU) cover the toggles that are easier to switch in game: `DYNAMIC SHADOWS` and `SHOOT FLASH` switch `DynamicModelShadows` and `Ps1ShootFlash` live and write the choice back to `[Fixes]`, so they agree with the configuration window, and `INVINCIBLE` stops the player's damage from landing at all (infinite health instead refills HP after each room tick).
- The UTILITY MENU also spawns and exits. `SPAWN < ZOMBIE >` is one row: LEFT/RIGHT scrolls through ZOMBIE, DOG, CROW and ITEM, and confirm places the shown entry 400 units in front of the player through the game's own room-table spawn (`00434850`, the function every entry of the room tables in `00430F90` calls), so a spawned actor is an ordinary native enemy that walks, bites and dies like the room's own. The actor is placed at the player's body sphere (`O+B8`, the point the native collision keeps against the floor), not at the view origin, so it stands on the ground instead of hanging in the air, and it never touches the room's persistent enemy-presence bits. The ITEM entry duplicates a pickup the current room already registered, at the new position and with the orientation the room itself handed the item manager, so its item data is loaded and it behaves like the original; a room without a registered pickup reports the failure instead of loading an id it never had. `QUIT TO TITLE` leaves the room through its own exit and lets the native boot state (main state 0, which sets the title up and enters state 2) open the title, and `QUIT GAME` posts the game's own window close, so the existing exit fix still runs. Actor types from 13 up (props and NPCs) are not exposed yet: their ids are not mapped in the room tables.
- The debug menu is hidden by default: `[SurvivorFix] DebugEnable=0` in `config.ini` keeps F2/F10 and the pad's `DebugMenu` button inert until it is set to 1, then the overlay is available from both. While it is open the pad drives it directly — d-pad or left stick moves, A confirms, B goes back — so no pad keys leak into gameplay.
- A missing `config.ini` is no longer a default-only installation: the wrapper writes the shipped template (the maintainer's own configuration) next to `d3d8.dll` on first launch, never over an existing file, so every option has a key to edit.
- DualShock 4 — the lightbar breathes with the player's health in the RE CONDITION colours: green (FINE) at 60-100%, amber (CAUTION) at 30-60%, danger red below that, with the breath period shrinking from 2.6 s to 0.65 s as health drops, and a dim blue idle light outside rooms. It is driven with the controller's own HID output reports (USB `0x05`, Bluetooth `0x11` with the Sony CRC32), so it works wired or wireless and needs no driver. The pad's own buttons, sticks and d-pad are read from its HID input reports and fed into the same bindings as an XInput controller, so a DualShock 4 works without DS4Windows or Steam Input; when one is present it takes precedence over XInput so the same pad is not counted twice. The pad also rumbles: a short burst for each shot and a stronger, longer one when the player is hit, carried by the same output report as the lightbar ([SurvivorFix] Ds4Rumble, on by default). The controller speaker plays a short gunshot burst on every shot; Windows only exposes that speaker as an audio endpoint over USB (v2 pad or the wireless adapter), so over plain Bluetooth the lightbar works and the speaker stays silent, which is logged once. `[SurvivorFix] DualShock4=1` and `Ds4Speaker=1` switch them.
- XInput support alongside DirectInput — the pad is polled whenever the game polls the keyboard and its keys are ORed into the keyboard state, so pad and keyboard work together (`[SurvivorFix] XInput=1`, `XInputDeadZone=0..95`). The right stick moves the crosshair (`[Gamepad] AimSpeed`, `AimInvertY`).
- Pad key bindings — every button and stick direction has its own entry in `[Gamepad]`, set to a key name (`Return`, `LeftShift`, `F5`, `Up`, or a scancode such as `0x39`), a mouse button (`LeftClick`, `RightClick`, `MiddleClick`, also `LeftMouseClick`/`Mouse1`/`Mouse2`/`Mouse3`) or one of the wrapper's own additions (`DebugMenu`, `QuickSave`, `QuickLoad`, `Fullscreen`), which the spare buttons can carry because the original configuration has no key for them. The mouse buttons are written into the game's DirectInput mouse state, so they fire, click through the native Save/Load menus and reach the wrapper's menus exactly like the real thing. RB ships as `LeftClick` because the game's own action key is also its confirm key: bound to a key, the fire button would shoot on every menu confirm. Start and Back ship unbound. Keyboard rebinding is still open.
- Raw Input support is still open.

# Installation

1) Head over to the [releases section](https://github.com/JacobMrox/Gun-Survivor-Classic-Rebirth/releases) and get the latest release.
2) Extract all files into your game installation directory, replacing any files when prompted.
3) GBIO.CFG is now auto-created by d3d8.dll (empty dummy) next to gun_bio.exe and d3d8.dll — no manual step needed. Existing GBIO.CFG files are never overwritten.
4) (Optional) Mod support: create `mods/mod_<id>/` with `manifest.txt` (see `source/mod_sdk.cpp` header), mirroring game-relative paths, or drop `mods/mod_<id>.7z` (non-solid, contents at root). Set `config.ini` `[Mod] Active = mod_<id>`; the `Module` DLL in the manifest is loaded from that folder.
5) This project is provided free, as-is, without warranty, and will continue improving over time

The embedded `MISC.BMP` is restored to `FIXRES\MISC.BMP` if missing. The wrapper
does not create a root-level copy or remove an existing one.

The release includes the x86 FFmpeg runtime required for movie playback:
`avcodec-61.dll`, `avformat-61.dll`, `avutil-59.dll`, `swscale-8.dll` and
`swresample-5.dll`. Keep all five beside `d3d8.dll` and `gun_bio.exe`.
They are dependencies of Classic Rebirth and are not supplied by the original
game. These builds also require the Microsoft Visual C++ x86 runtime.
MinHook is compiled into `d3d8.dll` from `source/minhook/`, so no
`minhook.x32.dll` is needed. The wrapper is not self-contained: it imports
the FFmpeg runtime DLLs listed above.
See `licenses/FFmpeg-NOTICE.txt` in the release for the FFmpeg license and source
information.

For maintainers: distribute the complete contents of `data/`, including `FIXRES/`,
the runtime DLLs, their hash manifest and `licenses/`. Run
`powershell -NoProfile -File scripts/verify-runtime.ps1` before packaging.
The AppVeyor packaging step checks the runtimes and archives the complete
`data/` payload.

Survivor-specific implementation, including the debug menu and PC adapter, lives
under `source/survivor_fix/`. The maintained Visual Studio project is
`source/d3d8-wrapper.vcxproj`; the Premake-generated project is under `build/`.
After regenerating with `premake5.exe vs2022`, run
`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-project-sync.ps1`
to check that both projects and the maintained Solution Explorer filters list
the same existing C/C++ sources and headers.
